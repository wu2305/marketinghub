# Knowledge card comparison · 六类知识卡片对照

One shared card foundation, six business compositions. The canvases below reuse the real view stories, including their filters, pagination and actions. They show the current implementation, not a claim of visual parity with the reference.

共用卡片基础，保留六类业务组成。下方直接展示现有业务故事，包含筛选、分页和操作；它们展示当前实现，不能视为已与静态 Demo 完全一致。

## Approved composition · 已确认的统一结构

The designer approved the four-part structure on 2026-10-09. Static Demo and Storybook use the same field order. / 用户于 2026-10-09 确认以下四部分结构，静态 Demo 与 Storybook 按同一顺序实现。

1. **Title + Enabled/Disabled:** one 24px line; title truncates with ellipsis. / 标题与可用状态同行，行高 24px；标题超长省略。
2. **Description:** up to two 18px lines, with height based on content. Cards in the same grid row stretch to the tallest card. / 描述每行 18px，最多两行，按实际内容占高；同排卡片以该排最高卡片统一高度。
3. **Metadata:** each existing field takes one 24px row, with 2.67px between rows; Creator rows with action icons also use 24px. Long values stay on one line with ellipsis; full text is available on hover. Missing fields have no placeholder rows. / 每个已有字段占一行，行高 24px、行间距约 2.67px，带操作图标的 Creator 行同样为 24px；内容单行省略，悬停可查看完整文字。没有的字段不占行。
4. **Actions:** Business Terms, Analytical Model and Scenario Reports put action icons on the right of the final Creator row. / 术语、分析模型、场景报表的操作图标位于最后一行 Creator 右侧。

Field order: Synonyms → Project / Domain / Data Model → Unit + Type (two equal columns in one row) → Recipients → Send time → Referenced Metrics / Report → Process → Creator. Synonyms and Recipients render each value as a rounded capsule in one non-wrapping row; long pill text uses ellipsis and the full value is available on hover. Process uses a status capsule without the availability dot. / 字段顺序：同义词 → 项目或域或数据模型 → 单位与类型（同行等宽两列）→ 收件人 → 发送时间 → 引用指标或关联报表 → 流程状态 → 创建者。Synonyms 与 Recipients 的每个值分别显示为圆角胶囊，保持单行不换行，长胶囊文字省略，悬停可查看完整内容。Process 使用胶囊标签，内部无圆点。

| Type 类型 | Existing rows 按顺序显示的字段 | Actions 操作 |
| --- | --- | --- |
| Report Context | Project | — |
| Metric Dictionary | Synonyms → Data model → Unit + Type | — |
| Email Reports | Data Model → Recipients → Send time | — |
| Business Terms | Synonyms → Data Model (if present / 有则显示) → Creator | Creator row / 创建者行右侧 |
| Analytical Model | Data Model → Referenced Metrics → Creator | Creator row / 创建者行右侧 |
| Scenario Reports | Report → Process → Creator | Creator row / 创建者行右侧 |

All six use 12px radius, 16px padding and 12px gaps between the main parts. Different field counts give different card heights; absent fields are not padded into equal-height cards. / 六类统一为 12px 圆角、16px 内边距、主要部分之间间距 12px。字段数量不同会产生不同卡片高度，不为缺失字段补空行。

## Storybook implementation · 实现方式

LibraryItem's `knowledge` variant implements the shared rhythm. Ordered `meta` entries provide each type's content; `secondary` pairs Unit and Type. Actions share the last metadata row. Process is the `process` variant of StatusBadge. The six canvases below reuse the real business view stories. / LibraryItem 的 `knowledge` 变体负责统一节奏；`meta` 按顺序提供各类字段，`secondary` 将 Unit 与 Type 配为同排；操作与最后一行元信息同行。Process 使用 StatusBadge 的 `process` 变体。下方六个示例直接复用实际业务视图故事。

Analytical Model has no Draft state or badge. Search and filter controls share DIN 2014, 12px regular text. All three managed card types share the same availability-based icon coloring. Shadow values and list column rules remain separate design settings. / Analytical Model 没有 Draft 状态或标记。搜索与筛选控件统一使用 DIN 2014、12px 常规字重。三类可管理卡片共用同一套基于 Enabled/Disabled 的图标配色。阴影数值和列表列数属于单独的设计设置。
